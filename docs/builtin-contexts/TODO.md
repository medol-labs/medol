## 分类和优先级

- **P1**：优先完善授权、状态、重复执行、恢复等闭环。
- **P2**：提升可用性、可维护性和明确的部署适配。
- **P3**：有实际业务需求后再实施的扩展，不是首版缺陷。
- **缺口**：现有文档或代码已能确认尚未覆盖；**核验**：需端到端验证后决定是否修改；**扩展**：现有边界之外的候选能力；**文档**：说明与实现需要校准。

保留现有设计边界：具体业务统计、权限范围、归档资格由业务定义；不为每项能力新增 DSL 关键字，不把所有支撑数据都改成 Axon 事件溯源，也不默认引入 Redis。

## 1. 身份与权限 — IdentityAccessManagement

依据：[使用说明](identity-access-management.md)、[模型](../../src/builtin-models/identity-access-management.medol)；生成器 `templates/identity-access-management/.../IamPermissionService.kt.tpl`、`BuiltinReadModelAuthIdentityRepository.kt.tpl`。

当前已有账号启停、角色/权限登记和授予、登录及服务账号 token。普通用户 JWT 解析会重新读取账号和权限并检查 active；`service-account` 分支使用签发时的权限快照，不能把两者写成同一种行为。

- [ ] **IAM-01 · P1 · 缺口**：补齐角色分配和角色权限授予的撤销建模，以及相应目录删除/失效和鉴权闭环。当前模型有授予命令，尚无对应撤销命令。验收：撤销后旧授权不能继续从投影读出；重复撤销和撤销后重新授予有明确语义。
- [ ] **IAM-02 · P1 · 缺口**：补服务账号 token 撤销、轮换及账号停用后的处置策略；明确授权快照的有效期。验收：旧 token 能按策略失效，不能只要求重新签发新 token 而让旧 token 无期限保留旧权。
- [ ] **IAM-03 · P1 · 核验**：验证普通账号停用、授权变化和登录之间的投影延迟窗口，以及多部署权限读取的一致性；明确何时必须从权威来源核验。不要把现有的普通 JWT active 校验重复列为未实现。
- [ ] **IAM-04 · P2 · 扩展**：与 TenantManagement 一起设计租户内角色分配作用域；验收同一账号在两个租户可拥有不同角色，平台管理员资格与租户业务角色分开。
- [ ] **IAM-05 · P2 · 文档**：校准手册关于“撤销事件”和“账号停用对已有 token”的表述，分别说明缺失的撤销命令、普通用户当前校验和服务账号快照限制。
